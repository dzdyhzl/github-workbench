# GitHub 仓库工作台任务书

> 本文件是插件创建的完整输入。新对话中的智能体仅凭本文件即可还原全部需求、已确认的实现细节、决策与验收标准，无需原对话上下文。全部实现细节均已经过逐项确认（2026-11-18）。

## 1. 背景与目标

在 DSH 中新增一个个性化页面（插件页面）+ 一个技能（skill），实现两块功能：

1. **仓库浏览**：展示 GitHub 账户的全部仓库，已本地链接的仓库点击卡片可跳转到对应工作区并开新对话；未链接的跳转 GitHub 网页。
2. **拒绝工作区管理**：保存"被拒绝建仓的工作区"表格；智能体首轮询问、用户拒绝后记录；用户可确认移除并顺势触发建仓。

## 2. 依赖与前置（已确认的风险）

- 本机需安装并登录 `gh` CLI（与"变更请求与工作树"插件同一依赖）。**未检测到 gh / 未登录时显示完整引导页**：安装命令、登录步骤（`gh auth login`）和"重新检测"按钮，检测通过后自动进入正常界面，不报错崩溃。
- **"打开新对话"的编程式跳转属未验证能力**，交给 Creator 实现；若不可行，退化为跳转到该工作区页面并提示用户手动新建会话（在页面中标注）。
- **多 GitHub 账户切换**：页面顶部（右上角）提供账户选择器。页面加载时用 `gh auth status` 枚举本机已登录的所有账户；切换用 `gh auth switch -u <用户名> -h github.com` 实现。注意：`gh auth switch` 改变的是本机 gh 的全局活动账户，会影响其他使用 gh 的流程（包括"变更请求与工作树"插件和智能体的 gh 命令）——**首次切换时弹一次确认框说明此副作用，确认后切换，之后不再弹**。
- **"移除后立即询问建仓"的可行性风险**：个性化页面能否主动向会话注入询问消息属未验证能力。降级方案——移除确认后页面展示一段可一键复制的提示词，用户粘贴到该工作区的新会话即可触发建仓（提示词模板见 §4）。

## 3. 页面设计

**位置**：`sidebar-left`（跨会话的全局功能，从左侧入口打开）。

**页面标题**：GitHub 仓库工作台

### 区域 A：GitHub 仓库列表

- **账户选择器（右上角）**：点击下拉展示本机所有已登录的 GitHub 账户（当前账户带标记），点击即切换并重新拉取本区域和区域 B 的数据。仓库列表按当前活动账户的视角获取；"本地链接匹配"基于本地 remote 的 owner/name 不受账户影响，但建仓等写操作作用于新账户。只有一个账户时选择器仅显示该账户名，下拉只有一项，退化为不可切换。首次切换弹确认框说明全局副作用，之后不再弹。
- 数据源：`gh repo list`（含个人、协作与组织仓库），**每个仓库卡片上标注归属类别（个人/协作/组织）**；显示仓库名、可见性、更新时间。
- 分页：首次 100 条，底部"加载更多"按钮每次追加 100 条。
- 刷新：打开页面时自动拉取一次；右上角（账户选择器旁）提供手动刷新按钮。
- 每个仓库标记本地链接状态：扫描本地工作区 git 仓库的 `remote origin` URL，按 `github.com/<owner>/<name>` 匹配。
- 提供搜索框过滤仓库列表。
- 点击行为（已确认）：
  - 链接到 1 个工作区 → 自动跳转该工作区并编程式新建对话（若编程式新建不可行，退化为跳转工作区页面并提示手动新建）；
  - 链接到多个工作区 → 弹出候选列表由用户选择，候选按"最近在 DSH 中使用过（有会话）优先"排序；
  - 未链接 → 打开该仓库的 GitHub 网页。
- **建仓按钮（区域 A 顶部）**：提供"为当前工作区建仓"按钮，点击展开建仓表单（与首轮询问共用同一表单逻辑，见 §4）。

### 区域 B：被拒绝的工作区表格

- **按账户隔离**：每个 GitHub 账户独立一份拒绝列表；同一工作区在账户 A 下被拒绝，切换到账户 B 后视为未拒绝、可再询问。表格上方显示当前账户名。
- 列：工作区路径、拒绝时间、备注。**备注默认留空，可随时手动编辑**（如"稍后再建"）。
- 数据持久化在页面数据中（本机保存，跨会话可用）。
- 每行操作：
  1. **"立即建仓"快捷按钮**：点击直接展开建仓表单（见 §4），不必先移除；
  2. **"移除"**：点击后先弹出确认，确认后从表格移除该记录，并触发建仓询问（优先尝试直接询问；若页面无法注入会话消息，则展示一键复制的建仓提示词，见 §4）。

## 4. 首轮检查询问的技能约定

新建一个技能（skill），内容约定智能体在会话首轮（用户发出第一条消息后，智能体在回复中顺带检查，不阻塞正常回答）：

1. 检查当前工作区是否为 git 仓库、是否有 GitHub remote；
2. 若未关联 GitHub → 询问用户是否创建仓库并 push（走建仓表单流程，见下）；
3. **若 remote 已存在但本地分支落后于远端或无上游** → 提醒用户是否有未推送的提交需要 push（只提醒一次，不强制）；
4. **建仓表单**（页面"为当前工作区建仓"按钮、首轮询问、拒绝表"立即建仓"共用）：
   - 仓库名：默认取目录名，可编辑；
   - 描述：可选填写；
   - 可见性：默认选中**私有**，可改公开；
5. **同名冲突**：提交表单时若当前账户下已存在同名仓库，提示冲突，用户可改名或改用关联已有仓库（git remote add + push）；
6. **推送安全**：push 前扫描工作区，发现敏感文件（.env、*.pem、密钥文件等）时**暂停并列出文件清单，等用户确认（继续推送或排除后继续），不自动继续**；
7. **推送成功后自动设置上游**：`git push -u origin <默认分支>`，之后的 git push 直接可用；
8. 用户拒绝 → 将该工作区路径写入页面区域 B 当前账户的表格；
9. 若工作区路径已在表格中 → 不再询问（这是"拒绝后不再问"的实现方式）；
10. **不纠缠规则**：每工作区每会话最多询问一次；用户忽略（未回答）不写入拒绝表格，但本会话不再重复问。
11. **账户**：首轮建仓使用 `gh` 当前活动账户（即页面上最近一次切换到的账户）；同名冲突处理见上第 5 条。

**建仓提示词模板**（区域 B 移除确认后展示，用户复制到该工作区的新会话）：

```
请在本工作区创建 GitHub 仓库并推送：
1. 用 gh 检查本目录是否已是 git 仓库，不是则 git init；
2. 和我确认仓库名（默认目录名）、描述和可见性（默认私有）；若当前账户下已存在同名仓库，提示我改名或改用关联已有仓库；
3. 检查是否包含 .env、密钥等敏感文件，发现时列出清单暂停，等我确认后再继续；
4. 用 gh repo create <仓名> --source . --push 创建，并用 git push -u 设置分支上游。
```

**边界约定**：
- 非 git 目录 → 询问是否先 `git init` 再建仓；
- remote 指向非 GitHub → 不询问，仅在页面区域 A 中按"未链接"处理。

## 5. 实施步骤

1. 调用 `propose_action`（`create_personalized_page`，`slot: sidebar-left`，标题"GitHub 仓库工作台"）提交页面方案，等用户点击创建，由后台 Creator 生成页面。
2. 页面生成后验证：仓库列表加载、匹配标记、三种点击行为、表格增删、一键复制提示词。
3. 编写首轮检查技能文件并启用，验证：新会话首轮询问、拒绝入表、表内工作区不再询问、移除后建仓流程。
4. 端到端验收：在一个未关联 GitHub 的工作区完整走一遍"询问 → 拒绝 → 表格 → 移除 → 建仓"流程。
